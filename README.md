# SEA — Schedule Exception Agent

국적 중소·중견 선사 **운항팀**이 기항 스케줄 변경을 받은 뒤, 확인·통보 준비를 마치도록 돕는 프로토타입입니다.

운영 판단을 AI가 대신하지 않습니다. 원문에서 확인 가능한 사실을 구조화하고, 직전 확정본과 비교하고, 회사가 정한 시간 창으로 확인할 일을 정리한 다음 담당자가 승인합니다.

- 저장소: https://github.com/hyunseook0606-dev/Sea
- 실행: 이 README의 **라이브** 항목 (배포 후 주소가 들어갑니다)

## 시연 (로그인 없음)

브라우저에서 연 뒤 상단 **시연**을 누릅니다.

| 시나리오 | 입력 | 결과 |
|---|---|---|
| A | HANARO 2508W, ETA 06:00→12:00, 부두 T2→T3, CY Cut-off 원문 유지 | 예외 전표. 여유시간·확인 항목·화주/내륙/내부 초안 |
| B | 같은 항차, 원문에 ETA 12:00 / ETB 10:00 | 원문 모순. 발송 잠금 |
| C | A와 같은 메일을 다시 수신 | 새 전표 없음 |

워크스페이스 **설정 → 워크스페이스 초기화**로 시드를 되돌릴 수 있습니다. 발송은 모의입니다.

## 하는 일 / 하지 않는 일

하는 일: 메일·PDF·엑셀 수신 → 필드 추출 → 항차 매칭 → 확정본 Diff → 여유시간 → 확인 체크리스트 → 3채널 초안 → 사람 승인 → 이력.

하지 않는 일: AIS·ETA 예측, TOS/야드, Cut-off를 ETA에서 자동 확정, 미승인 대외 발송, 부킹·장비·정산 등 선사 기간계 대체.

## 여유시간

가점 합산(`2+1=3`)이 아닙니다. 확정본과 신규 시각으로 시간을 계산합니다.

- ETA 검토 창 기본 6시간: Kim 등(2021) 부산 터미널 재계획 주기. 선석 최적화는 하지 않습니다.
- 연결 여유 = 연결 항차 ETD − 본선 ETD. 하한 기본 24시간: 부산 T/S 체류 문헌 하한 1일. 평균 체류는 임계로 쓰지 않습니다.
- 신규 ETA가 확정 ETB보다 뒤인데 ETB가 안 바뀌면 접안 시각을 다시 확인합니다.

숫자는 운영 위험의 확률·비용이 아닙니다. 기준정보 **규칙**에서 회사 값으로 바꿀 수 있습니다.
